# R4: fixing the six remaining flaws of the audit's §7 (plan, 2026-11-25)

The audit's §7 lists six remaining flaws and §8 six levers. This is what R4 does about each and why. R4 is exploratory
until lockbox 3, a new set of never-collected models, is scored once against predictions frozen before it is measured.
Lockbox 2 is spent: anything chosen by looking at its five points would be fitted to the test.

## Order of work

1. **v4 collection, `deploy` part** (`host/matrix_v4.py`): 64 configurations × 2 repeats, all hooks off, perf
   counters at `perf_event_paranoid=1`.
2. **Method choices on the R3 table** while v4 runs: intervals, selector, partial pooling. They are chosen on the
   v1+v2+v3 data that already exists and that R3 was evaluated on, then frozen as R4 code.
3. **R4 evaluation on the deployment table**: hooks-off configurations only, with v4 added. It is the first
   evaluation of the frozen choices on data they were not chosen on.
4. **Freeze, commit, tag `r4-frozen`**, then measure lockbox 3 and score it once.

## The six flaws

| # | flaw (audit §7) | R4 action | kind |
|---|---|---|---|
| 1 | hooks-on targets on pre-v3 data | v4 re-measures every hooks-on training configuration with the hooks off. The R4 Mode A target is deployment (hooks-off) energy, measured, and the hooks-on cells become an instrumentation study | collection |
| 2 | 90 % intervals cover about 80 % | conformal at the level of the base model: symmetric \|log residual\|, each held-out model weighted equally, finite-sample level (1−α)(1+1/K) | analysis |
| 3 | mbv3 / effb0 tail | first remove the hooks confound (most of the mbv3 gap is the hooks' +43 %); then partial pooling over architecture families, with lockbox 1 and 2 as siblings in training | analysis |
| 4 | harness I²R inside the label | board-level label `E_mon − R_rig·∫I²dt` beside the Monsoon label, with R fitted per rig (`audit/cable.py`). The Monsoon label stays primary because it has no model in it. Physical fix (short thick leads) still needs your hands | analysis + physical |
| 5 | kernel-blind counters | v4 cells are collected at paranoid=1. Mode L compares the R3 counter set with the kernel-visible set (context switches, kernel page faults, migrations) on the same v4 cells | collection |
| 6 | AUTO vs M4Physics on lockbox 2 | not decided from lockbox 2. Candidate selectors (current argmin, an M1×M4 geometric-mean ensemble, inner stacking) are compared on the R3 table's leave-one-model-out, chosen there, then confirmed on lockbox 3 | analysis |

Lever 6 of the audit (headline metrics on the inference segment and the forward phase) is a reporting rule. R4
headlines use forward and inference-segment metrics, with whole-cell numbers as secondary.

## v4 `deploy` (128 cells, about 2.5 h)

- **Replica (46 configurations):** every hooks-on configuration of v1 / v2 / v3 / lockbox 1 that has no hooks-off
  twin, on today's rig. That covers YOLO v8/11 at their clocks, sizes, threads and batches, int8 and fp16, plus the
  v1 classifiers at 1500 / 2000 MHz.
- **Sweep (18 configurations):** yolo12n, yolo12s, ConvNeXt-T, ViT-B/16, MaxViT-T and Swin-T at the clocks they lack.
  yolov8n at 320 / 960 px. ResNet-18, MobileNetV3, EfficientNet-B0 and ConvNeXt-T at 320 px.
- Hooks-on cells of v2 (same rig, four days earlier) pair with the replica, which turns the 2400 MHz hooks calibration
  of v3 into one over all clocks.

## Outcome (2026-11-25)

The details are in `analytics/reports/r4/README.md`. v4 collected all 128 cells. The R4 deployment table holds 83
configurations of 20 models.

| # | result |
|---|---|
| 1 | New-model energy MdAPE **3.9 %** (R3 9.9 %), MaxAPE 27 % (R3 40 %). The hooks added a median 4.3 % (up to 25 %) of energy, the same at every clock |
| 2 | Conformal intervals: **94 %** inside a nominal 90 % on new models (R3-style intervals: 87 %). They over-cover in the seen-model splits, which have 4–5 inner folds |
| 3 | mbv3 9.4 % (R3 32 %), effb0 3.3 % (R3 25 %). The tail was the profiler's overhead; family pooling adds nothing |
| 4 | Harness = 7.0 % of power. The board label gives the same errors (4.2 % energy). The leads still need rewiring by hand |
| 5 | The kernel counters are live (about 390 context switches/s) but uncorrelated with power (ρ −0.01). They make the live model slightly worse (L5 1.17 → 1.56 %), so the R3 counter set stays |
| 6 | On deployment data M4Physics is the weaker model (11.1 %), so AUTO keeps the job. AUTO_R4 ties on new models but is worse on new clocks (7.6 vs 4.2 %) |

Lockbox 3 (scored once, confirmatory): AUTO energy 6.9 % (R3 on lockbox 2: 13.6 %), 4/6 inside the 90 % intervals, power 2.0 %, calculator 3.5 %, live model 2.1 % vs lookup 5.8 % (`analytics/reports/r4/lockbox3.md`). Datasets: branches `dataset-2026-11-v4` and `dataset-2026-11-lockbox3`.
