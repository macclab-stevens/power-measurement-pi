# Analytics protocol note

Committed 2026-11-23 before any analytics code exists and before any model is fitted. It fixes what
is evaluated and how. Spec: `docs/superpowers/specs/2026-11-22-analytics-design.md`; plan:
`docs/superpowers/plans/2026-11-23-analytics.md`.

Amendments are allowed until the first model fit on real data (plan Task 16); each one is appended to
the log at the end with its date and reason. After the first fit, any change marks the affected
results exploratory.

## Data

- v1: `~/pi-power-data/v1` = branch `dataset-2026-10-matrix`, 224 cells. v2: `~/pi-power-data/v2` =
  branch `dataset-2026-11-v2`, 179 cells. Verified 2026-11-23 file by file against the branches
  (LFS files by sha256 and size, other files by git blob hash): v1 2,018 files and v2 2,137 files, 0
  mismatches, 0 missing. Extra local files are the unpublished `pi_console.log` / `pi_dmesg.log`.
- Disclosure: before this note, the controller viewed configuration-level summaries of v1 and v2
  (energy, latency and power per configuration, including the s- and m-models) while designing. No
  model was fitted. This is why a fresh lockbox (below) is the only pristine test.

## Targets

- Mode A headline: energy per image (mJ, gross board energy, measured frames 1..N of the forward
  mode, slip-overlapping frames excluded), per configuration (mean over QC-primary cells). Latency per
  image and mean power are reported with the same protocol.
- Mode L headline: absolute percentage error of whole-cell accumulated energy from 100 ms window
  power predictions.

## Splits (generated by `analytics/splits.py`, hashed)

- Headline split: S-LOMO (leave one base model out; 9 vision models; YOLO folds `sibling-seen`,
  classifier folds `new-architecture`).
- Also: S-LSO (n / s / m pairs; s = `interpolation`, n and m = `extrapolation`), S-LVO (INT8 variants;
  FP16 `unsupported`), S-LCO (1500 / 2000 / 2400 and 1500+2000 -> 2400), RANDOM 5-fold (sanity only).
- Mode L: leave one YOLO base model out over v2 counter cells.
- Lockbox: about 15 new cells collected after the `analytics-frozen` tag, scored once.

## Metrics

- Primary: MdAPE of the headline target per fold and pooled over test configurations.
- Secondary: MAPE, MAE, median signed % error (bias), RMSE, median absolute log error.
- Noise floor: median repeat CV of energy per image over configurations with >= 2 cells, printed in
  every table. Differences below it are "indistinguishable".

## Baselines and candidates (fixed order)

B0 median, B1 energy proportional to MACs per clock, B2 most similar seen model x MAC ratio, B3
log-linear OLS; M1 Ridge (alpha in logspace(-2, 4, 7)), M2 HistGradientBoosting (max_depth {2, 3, 4} x
learning_rate {0.05, 0.1} x max_iter {100, 300} x min_samples_leaf {3, 5}), M3 factored latency x
power; AUTO = best of M1-M3 by inner leave-one-model-out MdAPE.
Mode L rungs: L0 lookup, L1 calibrated PMIC, L2 busy / cycles ridge, L3 all counters (ridge, trees),
L4 L3 + PMIC. Mode L grids: ridge alpha in logspace(-2, 4, 7); trees max_depth {3, 5} x learning_rate
{0.1} x max_iter {200} x min_samples_leaf {50, 200}; every window weighted 1 / (windows in its cell).
Windows before a cell's first available PMIC read have no PMIC feature; L1 predicts them with the L0
lookup fitted in the same fold (share reported).

## Selection, intervals, tests

- Hyperparameters and AUTO chosen only by inner leave-one-model-out on each outer fold's training
  models.
- 90 % prediction intervals from inner residual quantiles (log scale, 5 % / 95 %); coverage reported
  per similarity class.
- Confidence intervals: cluster bootstrap over base models, 2,000 resamples, seed from config.
- Paired comparisons: Wilcoxon signed-rank on per-configuration absolute log errors, each learned
  candidate vs the best baseline (by MdAPE) within a split and target; Holm correction across that
  family.
- Applicability flag: novelty above the largest inner-fold novelty whose inner MdAPE was below 15 %.
- Seeds: 20261122 (master), 20261123, 20261124; headline reported for all three.

## Subgroups (fixed)

Split x similarity class; base model; precision; image size; threads; batch; clock; rig. Mode L also:
phase (idle, load_weights, warmup, forward, serve) and family (A, A-input, B, C, D, soak).

`q1_ctx_frac_flag = 0.03`, `q2_max_residual_ms = 1.0`, `q3_slip_frac_flag = 0.01`,
`q5_pv_rel_flag = 0.02`, `q6_sample_ratio_lo = 0.98`, `q6_sample_ratio_hi = 1.02`.
Observed (min / p50 / p95 / max): max residual 0.085 / 0.172 / 0.259 / 0.756 ms; slip share of measured

## Amendment log

- 2026-11-23, QC bounds: `q1_ctx_frac_flag` 0.01 -> 0.03. Reason: every cell spends about 1 % of its
  measured time in the Pi's 5 s sensor reads (p50 0.0103), so 0.01 flagged 57 % of cells and
  discriminated nothing; 0.03 sits above the observed maximum and flags only anomalies. The sensor-read
  samples stay in the energy (they are a real, uniform cost). Q1 is flag-only, so no cell changes
  status. Q5 is uninformative on this data: `P_W` is computed as `V_V x I_A` in alignment, so the
  discrepancy is exactly 0 in every cell; the rule is kept for future data.
- 2026-11-23, Mode L grids (before any Mode L fit): the plan said "grids as Mode A M1/M2"; that grid
  (leaves of 3-5 samples, 24 points) is unsuited to ~160k autocorrelated 100 ms windows and would cost
  hours per run on the NUC. Replaced by the 4-point tree grid above with leaves of 50 / 200 windows.
  The L1 fallback for windows with no PMIC read yet is fixed in advance.
- 2026-11-23, Mode L rung added AFTER a real-data fit (exploratory): during Task 14 development, a smoke
  run fitted all rungs on one real outer fold (yolo11m held out). Review then showed that the
  pre-registered L1 (per-window weighted least squares of P_W on a 5 s zero-order-hold PMIC snapshot)
  is attenuated by regression dilution: slope 0.47 against about 1.0 on cell means, whole-cell
  energy MdAPE 0.132 against 0.066 on that fold. L1 stays the primary, pre-registered PMIC rung. A
  second rung, `L1-cell` (OLS on per-cell means of P_W and pmic_W over the fold's training cells,
  predicted per window), is added and labelled exploratory everywhere it appears, because its design
  was informed by a scored fold. Also: Mode L folds are the 5 YOLO models with counter cells
  (yolov8n has none: its v2 cells are the counters-off `ref` family).

- 2026-11-23, lockbox freeze (Task 16b, before any lockbox cell exists): every model the lockbox is scored with
  is fitted on all training data once and pickled under `derived/models/` with its sha256 in `runs.jsonl`:
  Mode A primary = the AUTO-final candidate per target (`mode-a-extras`), secondary = B3 (all targets) and M3
  (energy) (`final-mode-a-secondary`); Mode L = all eight rungs (`final-mode-l`; grid by leave-one-YOLO-model-out,
  refit on every QC-primary counter cell). Pre-declared secondary Mode L rungs: L0, L1, L3-trees, L4-trees (the
  rest are reported too). `lockbox-predict` writes `reports/lockbox_predictions.csv` (committed before any
  lockbox cell is measured; intervals from the candidate's master-seed S-LOMO residual quantiles, applicability
  flag from the S-LOMO novelty threshold); `lockbox-score` loads the frozen pickles (sha256-checked) and that file,
  fits nothing, and writes `reports/lockbox.md`. The lockbox is scored once; any later change is exploratory.
- 2026-11-23, lockbox isolation (before any lockbox cell exists): the lockbox configurations are `yolo12n:640`,
  `yolo12n:320`, `yolov8n:480` (replaces yolo11n-seg per spec 9: the harness cannot run it unchanged), `resnet18:224`,
  `mbv3:224`. yolov8n is a training model, so `data.catalogue()` sets `mode_a_eligible` and `mode_l_eligible` to
  False for every `source == lockbox` cell, and every table, window, idle-table, Mode L, EDA and report path drops
  those cells explicitly through `data.training_cells`. `lockbox-score` builds its own tables from the lockbox cells.
  It reports yolov8n at 480 px separately as "new size of a training model" (novelty 0 but not in-sample).
- 2026-11-23, final-review corrections (before `lockbox-predict`; no model refitted, no frozen pickle touched): (1) Mode L paired
  comparisons now follow the Metrics rule above: Wilcoxon + Holm on per-configuration mean absolute log errors (configuration =
  Mode A key, mean over its held-out cells), with n configurations and n cells stated; the per-cell MdAPE stays the ladder estimate.
  (2) The learning curve fits each held-out YOLO model with the M1 parameters chosen in that model's own S-LOMO outer fold (the final-fit
  parameters had seen it); it is a separate command, `learning-curve`. (3) `mode-a-extras`, `final-mode-a-secondary` and `final-mode-l`
  refuse once `lockbox_predictions.csv` or `lockbox_frozen_models.json` exists (`--force` is logged and invalidates the lockbox).
  (4) `lockbox-predict` pins the sha256 of every tracked `analytics/*.py`, of `config.toml`, the commit and the idle table in the manifest;
  `lockbox-score` refuses a mismatch unless `--allow-code-change`, which labels the result exploratory, and checks the measured cells'
  layer tables against the static CSVs the predictions used. (5) A missing or NaN alignment residual is a Q2 failure (no cell changes status).
  The novelty threshold comes from S-LOMO (standardised over 8 models) while lockbox novelty is standardised over the 9 training models.
